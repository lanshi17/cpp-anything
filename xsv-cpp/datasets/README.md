# Datasets

Generated by `scripts/generate_datasets.py`. Nothing here is committed except
this file and the generator: a corpus is identified by its manifest, not by a
file in git.

## Profiles

| profile | small | medium | large | join | sort | wide | disk (approx) |
| --- | --- | --- | --- | --- | --- | --- | --- |
| `smoke` | 5k × 10 | 50k × 20 | 200k × 30 | 20k / 2k | 20k | 2k | ~40 MB |
| `standard` | 100k × 10 | 1M × 20 | 10M × 30 | 1M / 100k | 1M | 100k | ~5 GB |
| `full` | standard + 100M × 30 | | | 10M / 1M | 1M | 100k | ~20–35 GB |

`smoke` is for CI and harness checks. Numbers from `smoke` are not reportable
performance results; the file sizes are too small and startup dominates.

## Layout

```
datasets/
├── data/<name>.csv
└── manifests/
    ├── <name>.json
    └── index.json
```

Each manifest records: dataset name, profile, rows, columns, seed, encoding,
header flag, byte size, SHA-256, distribution, schema, file path, generator
version and a note. `index.json` aggregates the manifests and is the fingerprint
used by the benchmark runner.

## Determinism

- The PRNG is SplitMix64 implemented in the generator, not Python's `random`, so
  CPython upgrades cannot change the corpus.
- Row order, field order and formatting are fixed by the seed.
- `--force` rewrites; without it, an existing file is skipped only when its
  SHA-256 matches the manifest.
- Re-running the same profile must produce identical manifests (no timestamps).

## Distributions

| name | key property |
| --- | --- |
| `small/medium/large/xlarge_uniform` | uniform mixed-type rows |
| `high_card` | unique keys, hash-table stress |
| `low_card` | 8 distinct categories, duplicate chains |
| `skewed` | cube-of-uniform keys, hot buckets |
| `null_heavy` | 80% empty fields |
| `wide_rows` | 1–4 KiB fields, copies and cache misses |
| `sort_*` | random, sorted, reverse, duplicates, long strings |
| `join_left/right` | duplicate and skewed join keys |
| `complex_*` | BOM, CRLF, no trailing newline, empty, ragged, quoted newlines, unicode |

`complex_ragged` is intentionally invalid; it is used only by error-path cases.
